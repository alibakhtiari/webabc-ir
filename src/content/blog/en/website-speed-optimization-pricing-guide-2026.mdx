## 2. What Moves Your Quote Up or Down

Your final quote moves with four things: how much legacy bloat the site already carries, how complex the database and checkout logic are, whether the current host can serve cached content properly, and how many third-party scripts are embedded in templates. Cleaning up before optimizing usually costs less than optimizing around the mess.

- **Legacy plugin and theme weight.** A site carrying years of abandoned plugins pays for their removal first; dead code still ships to visitors until someone deletes it.
- **Database size and query health.** Large catalogues, unbounded postmeta growth, and slow queries push work into the e-commerce or custom tier regardless of the front end.
- **Hosting tier.** A server that cannot serve cached pages properly caps what any frontend optimization can achieve, and the fix is a migration, not a plugin.
- **Third-party embeds.** Chat widgets, A/B tools, and review widgets load on every page and are rarely inside your provider's default scope.
- **Scope of the redesign.** If templates must be rebuilt to remove unsized images and blocking styles, you are buying front-end work as well as tuning.
- **Whether you start with an audit.** The $200 to $450 audit is the cheap way to discover your site needs the $650 tier rather than the $2,500 one.

## 3. Google Core Web Vitals 2026 Standards

Google's 2026 Core Web Vitals are Interaction to Next Paint, Largest Contentful Paint, and Cumulative Layout Shift, scored from Chrome User Experience Report field data. The headline change is the retirement of First Input Delay in favor of INP, which measures the latency of every tap, click, and key press per visit rather than only the first one:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    2026 Core Web Vitals Thresholds                      │
├─────────────────────────┬───────────────────┬───────────────────────────┤
│ Metric                  │ Good Threshold    │ What It Measures          │
├─────────────────────────┼───────────────────┼───────────────────────────┤
│ INP (Interaction to     │ < 200 ms          │ Latency of all user taps, │
│ Next Paint)             │ (Ideal < 100 ms)  │ clicks, and key presses   │
│                         │                   │ throughout the visit      │
├─────────────────────────┼───────────────────┼───────────────────────────┤
│ LCP (Largest Contentful │ < 2.5 seconds     │ Render duration of main   │
│ Paint)                  │ (Ideal < 1.8 s)   │ viewport image or heading │
├─────────────────────────┼───────────────────┼───────────────────────────┤
│ CLS (Cumulative Layout  │ < 0.1             │ Visual unexpected shifts  │
│ Shift)                  │ (Ideal < 0.05)    │ and button jumping        │
├─────────────────────────┼───────────────────┼───────────────────────────┤
│ TTFB (Time to First     │ < 800 ms          │ Server response time to   │
│ Byte)                   │ (Ideal < 200 ms)  │ browser initial request   │
└─────────────────────────┴───────────────────┴───────────────────────────┘
```

Failing any of these thresholds in Chrome User Experience Report (CrUX) data directly harms your mobile rankings and reduces Google AI Overview extraction likelihood.

Each failing metric also tells your provider which line of the quote you are paying for. INP failures usually trace to JavaScript work on the main thread, so the fix lands in script deferral and bundle work. LCP failures usually trace to hero images and slow server response, so the fix lands in asset delivery and caching. CLS failures are layout work: reserved dimensions for media, ads, and injected banners. When a quote cannot map its price to one of these three, the scope is not defined yet.

## 4. Technical Scope of Enterprise Speed Tuning

Professional speed work covers four layers at once: asset modernization, JavaScript and CSS optimization, database and backend refinement, and network edge delivery. A caching plugin touches part of one layer only, which is why plugin-only tuning stalls well short of the thresholds Google scores you on:

```
┌─────────────────────────────────────────────────────────┐
│              The 4 Pillars of Real Speed Tuning         │
├─────────────────────────┬───────────────────────────────┤
│ 1. Asset Modernization  │ Lossless WebP/AVIF compression│
│                         │ and responsive image srcset   │
├─────────────────────────┼───────────────────────────────┤
│ 2. JavaScript & CSS     │ Code-splitting, critical CSS  │
│    Optimization         │ inlining, deferring 3rd party │
├─────────────────────────┼───────────────────────────────┤
│ 3. Database & Backend   │ Query indexing, transient     │
│    Refinement           │ cleanup, reducing TTFB < 200ms│
├─────────────────────────┼───────────────────────────────┤
│ 4. Network Edge Delivery│ HTTP/3, Brotli compression,   │
│                         │ Cloudflare Edge rules         │
└─────────────────────────┴───────────────────────────────┘
```

**1. Asset modernization.** Convert originals to modern formats at the CDN or build step, serve responsive sizes per breakpoint, reserve dimensions so nothing reflows, and let the largest viewport element load with priority while the rest waits.

**2. JavaScript and CSS optimization.** Split bundles by route, inline the styles needed for first paint, drop dead rules, and defer everything third-party until after the page is usable. Most recurring regressions enter through tag managers here.

**3. Database and backend refinement.** Clean transient and autoloaded data, index the queries that repeat, and remove slow plugins from the request path. This is the tier plugin-only fixes never reach, and it is why dynamic stores price higher.

**4. Network edge delivery.** Serve over HTTP/3 with Brotli compression, set explicit cache rules at the edge, and route visitors to the nearest point of presence so distance stops dominating the response time.

## 6. When Do You Need a Professional Speed Optimization?

Hire a professional when the failure shows up in field data or in your own users, not when a lab score dips below a round number. A cosmetic fix will not touch a systemic bottleneck, so the four signals below are the ones that justify paying for an engagement rather than a staging-copy cleanup:

1. Your Google PageSpeed Insights mobile score is below 75.
2. Search Console reports **"LCP issue: longer than 2.5s"** or **"INP issue: longer than 200ms"**.
3. Mobile visitors report lag during checkout or navigation.
4. Server resources spike to 100% CPU during traffic peaks.

## 7. How to Compare Speed Optimization Quotes

Compare quotes on scope, not headline price. Ask each provider for the specific fixes included, the baseline they will measure against, what falls outside the engagement, and what happens to the gains after the site publishes new content. A cheaper quote that omits database work or field-data verification is not cheaper.

1. **Ask for the baseline.** A provider who has not measured your pages before quoting is guessing at the tier you need.
2. **Require a line-item scope.** It should map onto the four pillars: assets, scripts, database, edge. Missing pillars mean missing work.
3. **Clarify what is excluded.** Redesigns, plugin development, and hosting migrations are the three exclusions that turn a fixed quote into a change order.
4. **Confirm how results are verified.** Gains should be re-measured on the same pages, in field data, after the work ships — not declared from a single lab screenshot.
5. **Ask who owns regressions.** Publishing new content reintroduces weight; find out whether a follow-up pass inside the engagement window is included.
6. **Check the access you must grant.** Server, CDN, and tag manager access are prerequisites. A quote that assumes none of them will stall on day one.
7. **Price the ongoing cost.** Quarterly audits are how gains hold; ask for that rate up front rather than renegotiating after the first decay.
