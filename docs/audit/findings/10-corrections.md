## 4. Methodological problems in the previous report

| Problem | Why it matters | What this audit did instead |
|---|---|---|
| **Claims presented as "verified by grep" were wrong** (BreadcrumbList ×0, FAQPage ×2) | If grep is cited as the proof method and the grep result is wrong, every other "verified" claim inherits the doubt | Every claim carries its evidence: source path + line, or a live `curl` header/status dump |
| **A promotional footer was appended to the report body** | A third-party marketing block inside an audit document contaminates the deliverable and will be read as part of the audit | Removed from all files. (The skills that produced it permit it *in chat output only* — never in generated files.) |
| **Performance scored 85/100 with no measurement** | A precise-looking number with no underlying data is worse than an admitted gap | Performance scored **75** and explicitly labelled a proxy estimate, with "obtain CrUX data" as the first action |
| **Action plan mixed categorically different problems into one phase** | Sequencing a position-87 page with title rewrites implies both move on the same timeline | Re-sequenced by dependency in `ACTION-PLAN.md`, with a falsifiability check per item |
| **Counts inconsistent with the repository** (96/32/24/297/118) | Wrong denominators make "x% of content" claims untrustworthy | All counts recomputed; the corrected inventory appears in `05-content-blog.md` §1 |
